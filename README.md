# AegisFlow

轻量交付治理平台。前端使用 React + TypeScript + Vite；Go 后端（鉴权（含可选 OIDC 单点登录）、账号与审计、项目、构建、部署目标、部署任务与审批、审查中心、安全扫描、攻击防御、知识库、独立密钥管理、项目自动化策略与审计 CSV 导出）位于 `backend/`。后端构建、CI 与生产镜像统一使用 Go 1.27 最新补丁：CI 的 Go 任务解析 `1.27.x`，镜像固定为 `golang:1.27-alpine` 的 digest，`security` 任务用最新 `stable` Go 扫描标准库漏洞；`backend/go.mod` 的 `go 1.26.0` 只是依赖最低要求。

后端启动、环境变量、接口及验证命令见 [Go 后端文档](backend/README.md)。前端登录已接入真实鉴权：access token 仅存内存，refresh token 使用 HttpOnly Cookie，支持恢复、自动刷新及退出撤销。账号管理提供真实接口与页面（自助修改密码、会话管理、管理员用户/角色/禁用与审计查询）；项目管理（P2）与最小构建闭环（P3 第一批）已接入真实接口：首页为项目列表，支持创建、修改、归档与恢复，并在项目行触发构建；构建列表与详情展示状态、命令快照与日志（SSE 推送，连接失败时回退游标轮询），可取消排队/运行中的构建，终态构建可一键重试（沿用原分支、使用项目当前命令）；构建触发、取消与重试写入审计表，管理员可在审计页按动作、对象、结果、操作人与日期范围筛选查询（筛选在服务端生效；`AEGIS_AUDIT_RETENTION` 可配置保留窗口，默认永久保留）。写操作按全局角色授权，并在其上叠加项目权限：项目可见性（public/private）与项目成员（maintainer/viewer）已实现服务端读过滤，私有项目对非成员返回 404；私有项目的写操作（改项目、触发/取消构建、管理成员）要求 maintainer，否则 403。前端项目列表显示公开/私有徽章并提供「成员」入口，创建向导可选可见性，成员管理页支持列表、添加、改角色与移除。部署目标（P4.1）已提供 admin-only 接口与页面：HTTP(S) 目标 CRUD、连通性探测、凭据以 AES-256-GCM 加密存储且从不回传（轮换可用 `AEGIS_SECRET_KEY_PREVIOUS` 做只读回退），前端支持列表/新建/详情、检查与替换/清除凭据；部署任务（P4.2）已支持创建、单 worker 执行（部署端点返回 2xx 后还会按目标健康路径复查，未健康即记失败）、事件游标、取消与回滚；部署审批（P4.3）已支持生产环境默认审批、批准/拒绝、超时过期与取消联动；可选审批 Webhook 通知支持 HMAC 签名、指数退避重试与至少一次投递（P4.4），审查中心（P5-A E4）的事件通知复用同一通道；部署按项目写权限授权（成员可对自己可写的项目发起、取消与回滚，审批仍 admin-only）。部署记录、部署详情与审批页面已接入：服务端分页列表与项目/状态筛选、新建部署、详情（事件轮询、取消、回滚与「回滚自 #n」）以及审批中心（状态筛选、批准/拒绝+理由）。安全扫描与攻击防御事件（P5 剩余模块批次 A，集成优先）已交付真实后端与页面：外部扫描/检测工具通过签名入站接口（`AEGIS_INGEST_WEBHOOK_SECRET`，HMAC-SHA256 + ≤300s 时间窗 + delivery 幂等）回写扫描结论与防御事件，AegisFlow 只做登记、审计与展示而**不自研扫描或检测引擎**；扫描结果按项目可见性查询（全局/项目列表、verdict 筛选、详情与报告外链），防御事件仅管理员可读并可确认（`security_event.ack` 与状态变更同事务），未设置该密钥时两个入站接口返回 503。知识库与独立密钥管理（P5 剩余模块批次 B）已交付真实后端与页面：知识库以纯文本/Markdown 原文存储，所有已登录角色可读、管理员可新建/编辑/删除并在同一事务写审计（detail 只含 id/title，不含正文），前端详情使用安全渲染器（禁用原始 HTML、链接仅允许 http(s) 且带 `rel="noopener noreferrer"`，XSS payload 按文本显示）；独立密钥管理页 `/keys` 仅管理员可见与可调用，密钥值在写入前以 AES-256-GCM 加密（复用 `AEGIS_SECRET_KEY`，AAD 绑定 `aegisflow:secrets:<id>`，轮换递增 `key_version`），列表只返回名称/创建人/时间等元数据、值永不回传，未配置密钥时写入返回 503 `secrets_not_configured`，列表与删除仍可用。项目自动化策略与审计 CSV 导出（P5 剩余模块批次 C）已交付真实后端与页面：每个项目可配置 `requireReview`（创建与回滚必须关联同项目已批准审查，优先级高于环境变量门禁）与 `requiredScanVerdict`（`passed` 时项目最新扫描必须存在且结论为通过），策略存数据库、默认关闭，无策略行时既有部署行为完全不变；写入复用审查决策权限（admin 或项目 maintainer），其他角色只读，写入与 `policy.update` 审计同事务；前端在项目列表「策略」入口打开 `/projects/:id/policy`，部署表单在选择项目后按策略显示中文提示。审计 CSV 导出 `GET /api/v1/audit/export.csv`（admin-only）复用审计筛选（from/to/action/objectType/result/actor），按 RFC 4180 转义、表头 `id,createdAt,action,objectType,objectId,result,actor,detail`、最多 10000 行并在超出时返回 `X-Audit-Truncated: true`，不含凭据/令牌/请求正文；设置页审计面板新增「导出 CSV」按钮（带当前筛选、文件名含日期时间）。

面向多人、多实例部署，采用 PostgreSQL 共享存储、Redis 共享限流与同源负载均衡；双实例联调样例见 [部署说明](deploy/README.md) 和 [Compose](compose.yaml)。角色矩阵与会话安全约定见 [鉴权契约](docs/auth-contract.md)，机器可读接口见 [OpenAPI](backend/openapi.yaml)。审查中心门禁式后端（审查请求、maintainer/admin 批准或拒绝、发起人/维护者取消、项目内编号与审计、全局审查列表、签名外部结果回写与审查事件通知）已交付 API、数据与测试，并提供可选的部署审查门禁（`AEGIS_DEPLOY_REQUIRE_REVIEW_ENVIRONMENTS`，默认关闭；开启后目标环境要求已批准审查，与既有审批叠加）；审查中心前端已接入（全局列表与项目/状态筛选、审查详情、发起审查对话框、维护者/管理员批准或拒绝并记录理由、发起人可取消，详情页回显外部结果：来源、中文 verdict 徽章、摘要与报告外链），部署表单可关联已批准审查，部署详情展示关联审查链接；安全扫描前端已接入（全局列表与项目/结论筛选、中文 verdict 徽章、详情页展示来源/工具/摘要与报告外链），攻击防御事件页仅管理员可见（严重度/状态筛选、开放事件二次确认后写审计）；知识库前端已接入（列表搜索/分页、Markdown 详情安全渲染、管理员新建/编辑/删除），独立密钥管理页 `/keys` 仅管理员可见（元数据列表、新建含二次确认、轮换与删除，页面与接口均不回显值）；项目自动化策略页（项目列表「策略」入口，admin/maintainer 可写、可见者只读）与设置页审计面板的 CSV 导出已接入真实接口，`/policies`、`/audit`、`/audit/report` 仍是未实现占位（策略按项目配置、审计导出在设置页提供，不另设独立入口）；身份侧 OIDC 单点登录已交付（真实授权码 + PKCE，可选自动开通 member；LDAP 未开始）；多租户已交付阶段 F1（租户表、用户/会话/JWT/审计租户归属、默认租户与 `AEGIS_DEFAULT_TENANT_SLUG`）与阶段 F2（全量业务数据租户隔离 + `cmd/tenant` 租户运维 CLI）：14 张业务表带 `tenant_id`，项目/构建/部署目标/部署/审批/审查/扫描/防御事件/知识库/密钥/策略的全部读写按会话租户过滤，跨租户一律 404，名称与投递幂等键等唯一约束按租户区分，HMAC 入站证据归属资源租户，worker 与通知 outbox 携带租户，租户可用 CLI 开通、列出、禁用/启用；登录页租户标识输入、界面租户展示、双租户 E2E、子域/路径路由、租户切换与平台控制台仍未开始（F3 及以后）。构建侧未做阶段与产物、构建缓存与私有仓库凭据。未实现的占位页面恒定标记未实现，真实鉴权没有 mock 回退。

## 构建执行边界（P3 第一批）

构建命令在系统临时目录用 shell 执行，超时由 `AEGIS_BUILD_TIMEOUT` 控制，单次工作区大小受 `AEGIS_BUILD_DISK`（默认 2g）约束（看门狗无法测量目录大小时 fail-closed 取消构建）；状态为排队/运行/成功/失败/取消/中断。多副本通过 PostgreSQL 会话级租约保证同一时刻只有一个 worker：只有持锁副本在启动时把遗留的运行中构建标记为中断并领取任务，其余副本待命，持锁进程消失后自动接管。执行隔离由 `AEGIS_BUILD_SANDBOX` 选择：`container`（生产推荐）为每个构建启动一次性容器——无网络、只读根文件系统、只有构建目录可写，CPU/内存/进程数硬上限，非 Windows 平台以服务进程 uid/gid 的 `--user <uid>:<gid>` 运行（容器内非 root），超时或取消会杀掉容器；`user`（仅 Linux，服务需以 root 启动）通过 `setpriv` 把构建降权到 `AEGIS_BUILD_USER` 指定的专用账号（拒绝 uid 0 的账号）；`none`（默认）以服务进程身份执行，仅供开发。三种模式都不继承 `AEGIS_*` 服务凭据，`HOME`/临时目录位于 0700 构建目录，输出与 system 行在落库前脱敏（多行 PEM 私钥块、任意 scheme 内联凭据、HTTP Basic 均已覆盖，fail closed）。`AEGIS_BUILD_CLONE=true` 时先浅克隆项目仓库（`repoUrl`）再在仓库内执行命令，只支持无凭据的 https / `git@` 地址，本地路径需额外开启 `AEGIS_BUILD_ALLOW_LOCAL_REPO`，私有仓库凭据本批不支持。日志与状态优先经 SSE 推送（前端用带 Bearer 的 fetch 流式读取，token 不进 URL），连接失败时自动回退到 `after` 游标轮询。

## 本地联调

1. 启动 PostgreSQL、Redis，按后端文档设置连接 URL、共享密钥、首次管理员账号和密码，在 backend 目录启动 Go 服务（127.0.0.1:8080）。
2. 在项目根目录运行 `npm install`、`npm run dev`，访问 **http://localhost:5173**。Vite 将 /api 转发至 Go 服务。
3. 使用初始化的管理员账号登录；如配置了 `AEGIS_OIDC_*`，登录页会在密码表单上方显示「企业单点登录」入口（未配置时无任何变化）。项目（含自动化策略）、构建、部署、审查、安全扫描、知识库、账号安全与用户管理均为真实功能；攻击防御事件页与独立密钥管理页仅管理员可见；设置页审计面板支持筛选与 CSV 导出。创建带「构建命令」的项目后可在项目行直接触发构建。未接入的模块恒定显示未实现声明，不提供演示数据开关。
4. 如修改访问域名或端口，同步配置后端 `AEGIS_ALLOWED_ORIGINS`。生产使用 HTTPS 并启用 `AEGIS_COOKIE_SECURE=true`。

构建：`npm run build`；规范检查：`npm run lint`；单元测试：`npm test`；浏览器测试：`npx playwright install chromium` 后运行 `npm run test:e2e`（需设置专用测试服务的 `AEGIS_E2E_DATABASE_URL`、`AEGIS_E2E_REDIS_URL`，并保持 5173 和 8080 端口空闲；本地重复运行前可用 `pwsh scripts/reset-e2e-db.ps1` 重置一次性库，加 `-WhatIf` 只打印 SQL）。CI 在 [`.github/workflows/ci.yml`](.github/workflows/ci.yml) 的 backend/frontend/e2e 之外还执行：前端 `npm audit --audit-level=high`；`security` 任务的 `govulncheck ./...`（阻断门禁；用最新 stable Go 扫描标准库）；`windows` 任务在 Windows 上检查 `gofmt -l ./cmd ./internal` 为空、`go vet ./...`、`go build ./...` 以及不依赖 PostgreSQL/Redis 的 `go test ./internal/config ./internal/metrics`；`infra` 任务的 `docker build -t aegisflow-api:ci ./backend`、`docker compose config -q` 与网关 `nginx -t`。依赖升级 PR 由 [`.github/dependabot.yml`](.github/dependabot.yml) 每周生成，仍需 owner review 后合并。

开发进度、阶段验收与验证记录随 PR 维护（过程文档只在本地，不入库，见 [项目约束](AGENTS.md)）。贡献流程与协作约束见 [项目约束](AGENTS.md)：所有变更走 PR，且每个 PR 需仓库所有者 review 后合并。
